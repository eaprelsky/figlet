# Figlet

**Читайте вглубь: автор → книга → глава → раздел → абзац.**

[Открыть приложение](https://figlet.eaprelsky.ru)

Figlet — открытое приложение для нелинейного чтения. Вместо длинного диалога с нейросетью вы перемещаетесь по карте произведений и меняете масштаб чтения. Кнопка **+** показывает больше деталей на меньшем участке оригинала, **−** собирает более общий обзор. Стрелки листают страницы на текущем уровне. При изменении масштаба сохраняется точка в оригинале.

## Что умеет

- Карта автора: основные идеи, вклад, важные произведения и рекомендуемый порядок чтения.
- Автоматический поиск текстов в русской и английской Викитеке. Для книг на нескольких страницах импортируются главы, предисловия и послесловия (до 40 страниц, с явным предупреждением о пропусках).
- Импорт по публичному URL и из TXT, Markdown, HTML, FB2, EPUB, PDF с текстовым слоем.
- Централизованный каталог: сервер хранит оригинал файла, разбор и издание (редакцию) каждой книги. Одинаковые тексты в разных обложках сводятся в одну работу; редакции, отличающиеся только мусором вроде PDF-разметки, объединяются в самый полный текст, а агент проверки оценивает качество каждого издания.
- Определение книги при загрузке: сервер пробует распознать название и автора по началу текста и имени файла; если не уверен — читатель подтверждает данные в диалоге. Книгу можно переименовать, загрузить файл заново с новым названием или удалить для повторной загрузки.
- Полный разбор книги в фоне: сначала строится карта раздела, который читатель открыл, затем остальные — по важности из родительских разборов. Прогресс виден в шапке книги.
- Ленивые обзоры и оценки важности: готовые разборы и карты авторов берутся из общего серверного кэша. Одновременные запросы одного разбора используют одну генерацию.
- Общая библиотека книг из публичных URL и загрузок. Новые читатели открывают готовый оригинал и структуру, в том числе по прямой ссылке на фрагмент.
- Бесплатно — 5 новых книг в неделю на серверном ключе; дальше — свой ключ (OpenAI-совместимый или Anthropic шлюз) или подписка через YooKassa.
- Необязательные аккаунты: логин и пароль (scrypt-хэш в базе), подписка переносится между устройствами; без входа всё живёт в куках браузера. Роль администратора назначается через `FIGLET_ADMIN_LOGINS` и даёт доступ к чистке реестра книг.
- Оригинал с отдельной листалкой; вопрос по разделу или выделенному абзацу открывается дополнительным инструментом.
- Светлая, тёмная и системная темы; мобильная вёрстка; самостоятельно размещённые шрифты.
- Личная библиотека, карта авторов, исходные тексты, разборы, ответы и позиция чтения сохраняются в IndexedDB. Cookies содержат тему, модель, размер шрифта, идентификатор читателя и сессию: книги не помещаются в лимиты cookies.
- Экспорт / импорт библиотеки. После первого онлайн-открытия и установки service worker оболочка и сохранённые книги доступны без сети. Новые разборы и загрузки требуют подключения.

## Запуск

Нужен Node.js 24 или новее.

```sh
npm ci
cp .env.example .env
# Заполните DEEPSEEK_API_KEY в .env, затем:
node --env-file=.env --watch server/index.mjs
# В другом терминале:
npx vite
```

Для запуска без общего ключа достаточно `npm run dev`: читатель вводит личный ключ в настройках. Ключ по умолчанию живёт в памяти вкладки; по явному выбору сохраняется в sessionStorage до её закрытия. Он не попадает в экспорт библиотеки.

Сборка и запуск:

```sh
npm run build
node --env-file=.env server/index.mjs
```

Сервер по умолчанию слушает `127.0.0.1:3400`. Можно задать `PORT` и `HOST`.

## DeepSeek и другие провайдеры

По умолчанию используется прямой API `https://api.deepseek.com` и `deepseek-flash`. На 11 сентября 2026 года `/models` отдаёт `deepseek-flash` и `deepseek-v4-pro`; идентификатора `deepseek-v4.1-flash` не существует — новая флеш-модель доступна под именем `deepseek-flash`, а прежний `deepseek-v4-flash` молча синонимится к ней. Идентификатор модели задаётся через `DEEPSEEK_MODEL` и доступен в настройках.

Читатель после исчерпания бесплатных книг может указать свой шлюз: базовый URL, модель и ключ — OpenAI-совместимый (`/chat/completions`) или Anthropic (`/v1/messages`). URL должен быть публичным HTTPS-адресом на стандартном порту; ключ передаётся только в шлюз читателя и не сохраняется на сервере. Не передавайте личный ключ стороннему шлюзу, если не доверяете ему. Имя заголовка `x-deepseek-key` исторически общее для этого приложения; ключ никогда не отдаётся в ответах API.

Модель получает текст только текущего раздела. Для очень крупных разделов передаётся явно обозначенная выборка до 140 000 символов; более глубокий уровень даёт более полный контекст. Вопросы обрабатываются отдельно. Рекомендации до загрузки текста основаны на знаниях модели, а не на якобы прочитанной книге. Цитируемый оригинал хранится отдельно от AI-ответа.

## Развёртывание

```sh
cp .env.example .env
# Добавьте ключ в .env и ограничьте доступ: chmod 600 .env
docker compose up -d --build
```

Контейнер слушает только `127.0.0.1:3400` на хосте. В `deploy/` лежат конфигурации Nginx для `figlet.eaprelsky.ru`; адаптируйте домен и пути сертификата для своего сервера. Сначала настройте HTTP challenge, выпустите сертификат, затем включите HTTPS-конфигурацию. Перед перезагрузкой Nginx выполните `nginx -t`.

Серверный кэш хранится в SQLite (`CACHE_DB`, по умолчанию `.figlet-data/cache.sqlite`). Docker использует постоянный том `figlet-data` в `/app/data`; пересборка и перезапуск сохраняют библиотеку и разборы. Оригиналы файлов лежат в `files/` рядом с базой. Не удаляйте том при обновлениях. Для согласованной резервной копии используйте SQLite backup API или остановите сервис перед копированием БД вместе с WAL. Личные позиции и офлайн-копии остаются в браузере.

Для подписок задайте `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` (магазин Figlet), затем добавьте в личном кабинете YooKassa webhook `https://<домен>/api/billing/notify` на событие `payment.succeeded`. Без ключей кнопка подписки скрыта, а возврат со страницы оплаты подтверждается опросом статуса.

Ключ кэша включает версию обработки, провайдера, модель и содержимое запроса, включая текст и структуру раздела. Ключи API в БД не записываются. Ошибки не кэшируются. Совпадающие запросы объединяются внутри одного процесса; текущая конфигурация предполагает один экземпляр сервиса. При изменении промптов повышайте `VERSION` в `server/cache.mjs`. Ранее созданные клиентские AI-ответы не принимаются в общий кэш как доверенные; новые серверные результаты автоматически становятся общими.

## Проверки

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

Проверяются сохранность оригинала и дерева глав, порядок EPUB, FB2, защита импорта от SSRF, ограничения контекста, API, переход от автора к книге, семантический zoom с сохранением позиции, повторное использование кэша, листание оригинала, вопросы к абзацам и мобильная тема; каталог работ и редакций (сведение дубликатов, объединение редакций, агент проверки), аккаунты с хэшированием паролей, недельная квота книг и подписка YooKassa с вебхуком, полный разбор книги с приоритетами.

Браузерные тесты используют предсказуемые AI-ответы, чтобы не тратить ключ и не зависеть от модели. Живое подключение к DeepSeek проверяется отдельно при развёртывании.

## Ограничения и приватность

На `figlet.eaprelsky.ru` подключён общий счётчик Яндекс Метрики `112004441`: посещения и переходы внутри приложения. На localhost и чужих доменах он не запускается. Вебвизор отключён; тексты книг, вопросы и API-ключи не передаются в пользовательских параметрах аналитики. Подключение находится в `src/analytics.ts`, без дублирующей вставки через Nginx.

- Оригиналы из публичных URL, загруженные файлы и новые разборы сохраняются на сервере и входят в общую библиотеку: это ядро каталога работ и редакций. Копии для офлайн-чтения, позиция и вопросы остаются на устройстве. Очистка данных сайта не удаляет общий кэш.
- Загруженные файлы проходят через сервер: сохраняются оригинал (по SHA-256, без дубликатов), разбор и запись в каталоге; сервер сверяет редакции и объединяет самые полные тексты. Личные вопросы не попадают в общий кэш. Service worker не кэширует API; сервер не журналирует тела запросов и ключи.
- Лимит файла — 10 МБ; текста — 2,5 млн символов. Превышение объёма явно отмечается. Для сканов PDF нужен внешний OCR; порядок сложных PDF-колонок может потребовать проверки.
- Нет обхода платного доступа и поиска по пиратским библиотекам. Другой публичный источник можно добавить по URL. Права на тексты сохраняются у соответствующих правообладателей; MIT относится к коду Figlet.
- Импорт URL разрешает только публичные HTTP(S)-адреса, проверяет каждый redirect и закрепляет проверенный IP соединения. Доступ к локальной сети и metadata endpoints запрещён; то же ограничение действует для своих шлюзов AI.
- Публичный сервис ограничивает API-запросы: 100 за 15 минут, 40 новых AI-запросов в час на IP; до 4 одновременных AI-запросов; до 500 AI-запросов в сутки на процесс (`AI_DAILY_REQUEST_LIMIT`); 5 новых книг в неделю на читателя без своего ключа и подписки (`FREE_BOOKS_PER_WEEK`). Попадания в кэш и ожидание общей генерации не расходуют AI-лимиты. Суточный счётчик сбрасывается при перезапуске.
- Пароли аккаунтов хранятся только как scrypt-хэш с солью; сессии — HttpOnly cookie на 90 дней. Восстановления пароля нет: модель угроз лёгкая, красть в сервисе нечего.
- Значимость — субъективная оценка AI, а не универсальный рейтинг. Разборы и ответы могут ошибаться; сверяйтесь с оригиналом.

## Стек

React, TypeScript, Vite, Express; IndexedDB (`idb`); Cheerio, fflate и pdf-parse для извлечения текста. Прямой HTTP API DeepSeek. Docker + Nginx. Лицензия кода — MIT.
